> **구직 폴더(`{user_dir}`) 확인:** 먼저 현재 작업 디렉터리에서 `CareerLoop/` 폴더(또는 한 단계 위·아래)를 찾아 그 폴더가 들어 있는 디렉터리를 `{user_dir}`로 쓴다. 홈 디렉터리 전체를 검색하지 않는다. 작업 디렉터리에서 찾지 못하면 사용자에게 경로를 묻고, 그래도 없으면 `/careerloop:launch`를 안내한다.

resume에서 ATS에 불리한 서식, 키워드 공백, 서사의 약점을 점검한 뒤 구체적인 인라인 수정안을 제안한다. 분석은 `resume-coach`를 호출해 수행한다.

이 스킬은 명시적으로 요청할 때만 실행된다. `tailor-resume` 뒤에 스스로 실행되지 않고, resume를 붙여넣었다고 실행되지도 않는다. 사용자가 수정안을 고르기 전에는 텍스트를 바꾸지 않는다.

## 워크플로

### 1. resume 식별

맥락에서 resume를 확인한다. 우선순위 순서:

1. 이번 세션에서 `tailor-resume`가 방금 생성한 resume
2. 대화에 직접 붙여넣은 내용
3. 사용자가 언급한 아티팩트 이름이나 파일명 — `{user_dir}/CareerLoop/artifacts-index.json`에서 찾아 파일을 읽는다

resume를 식별할 수 없으면:
> "어떤 resume를 점검할까요? 여기에 붙여넣거나 파일명을 알려주세요."

### 2. job description 확보

키워드 일치 분석에는 JD가 필요하다. 맥락에 있는지 확인한다:

- `tailor-resume`가 방금 실행됐다면 JD는 이미 맥락에 있다 — 그것을 쓴다
- 사용자가 resume와 함께 JD를 붙여넣었다면 그것을 쓴다
- 맥락에 JD가 없으면 묻는다:
  > "키워드 커버리지를 점검하도록 job description을 붙여넣어 주세요. 건너뛰면 서식과 서사만 점검합니다."

사용자가 건너뛰면 서식과 서사 점검만 진행하고, 결과에서 키워드 일치는 빠졌음을 알린다.

### 3. resume-coach 호출

resume 텍스트와 JD(있는 경우)를 `resume-coach`에 전달한다. 에이전트가 ATS 점수 규칙과 서사 코칭 규칙을 적용해 문제 목록을 돌려준다: 실패한 점검, 문제가 된 텍스트, 제안하는 수정안.

### 4. 인라인 수정 제안 제시

발견 사항을 우선순위 목록으로 정리한다 — 영향이 큰 문제부터. 각 문제마다 원문과 제안하는 재작성을 나란히 보여준다:

```
ATS 점검 — {filename or "이 resume"}
{n}건의 문제 발견

1. {점검 이름}  [HIGH / MEDIUM / LOW]
   원문:  "{resume의 정확한 텍스트}"
   수정:  "{구체적인 재작성 제안}"

2. {점검 이름}  [HIGH / MEDIUM / LOW]
   원문:  "{정확한 텍스트}"
   수정:  "{구체적인 재작성, 직접 대체가 불가능하면 지시 사항}"

...
```

**우선순위 수준:**
- **HIGH** — 탈락이나 신뢰성 문제를 일으킬 가능성이 높다: 뒷받침되지 않거나 검증할 수 없는 주장, 누락된 연락처, resume에 근거가 없는 JD 필수 요건(공백으로 보고하고 키워드는 절대 끼워 넣지 않는다)
- **MEDIUM** — 점수를 의미 있게 깎는다: 약한 동사 시작어, 검증 가능한 결과가 없는 성과, 전칭 또는 배수 표현, 비표준 섹션 헤더나 다단 레이아웃(resume를 ATS에 업로드할 때만)
- **LOW** — 다듬기 항목: 일관되지 않은 날짜 형식, 사소한 문구 개선

목록은 10건으로 제한한다. 더 있으면 알린다:
> "우선순위가 낮은 항목이 {n}건 더 있습니다. HIGH와 MEDIUM 항목을 먼저 처리하세요."

문제가 없으면:
> "ATS 문제가 없습니다. 이 resume는 파싱과 키워드 커버리지 면에서 깨끗합니다."

### 5. 수정 적용

목록을 보여준 뒤:
> "모든 수정을 적용할까요, 아니면 적용할 번호를 알려주세요. 그대로 두려면 'skip'이라고 말씀해 주세요."

**사용자가 전체 또는 특정 항목을 확정하면:**
- 수락한 수정을 resume 텍스트에 적용한다
- 사용자가 결과를 검토할 수 있도록 수정된 섹션을 인라인으로 보여준다
- 이 resume가 저장된 아티팩트라면 묻는다:
  > "수정한 버전을 저장할까요? **{filename}**을(를) 덮어씁니다."
  - 예: 수정한 내용을 파일에 쓰고 `artifacts-index.json`을 오늘 날짜로 갱신한다
  - 아니오: 사용자가 직접 복사할 수 있도록 수정된 텍스트를 표시한다

**사용자가 건너뛰면:**
- 아무것도 수정하지 않는다
- 확인한다:
  > "변경하지 않았습니다. `/careerloop:tailor-resume`를 실행하면 새로 다시 생성합니다."

### 6. 이 스킬이 하지 않는 것

- 점수 카드를 만들지 않는다 — 공식 40/35/25 점수는 `/careerloop:resume-score`를 쓴다
- 경력, 수치, 스킬을 지어내지 않는다 — 수치가 없으면 수정안은 지어내지 않고 "본인의 수치를 추가하세요"라고 쓴다
- 맥락에 이미 있는 정보를 사용자에게 요청하지 않는다
